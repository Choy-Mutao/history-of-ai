# 2026-08-16 · Phase 3：GitHub Actions 定时采集工作流

> 承接 `2026-08-16-phase2.md`。本文记录 Phase 3 的实现与待验证项。

## 实现内容

新增 `.github/workflows/collect.yml`：

- 触发：`schedule: cron '17 1 * * *'`（UTC 01:17 ≈ 北京时间 09:17，避开整点）
  + `workflow_dispatch` 手动触发；
- 环境：ubuntu-latest + Node 22（与 deploy-ecs.yml 一致）；
- 步骤：`npm ci` → `npm run collect` → `npm run collect:report` →
  `peter-evans/create-pull-request@v7` 提交自动 PR；
- PR 范围严格限定 `add-paths: src/data, src/reports`，**不触碰 docs/**；
- 固定分支 `auto/collect`（重复运行更新同一 PR），标题带日期，打 `collection` 标签；
- 权限：`contents: write` + `pull-requests: write`（最小必要集）。

## 验证情况

- YAML 语法已通过 `yaml-lint` 校验；
- 采集与报告两个 npm script 已在 Phase 1/2 本地跑通；
- **工作流的端到端验证（cron 触发、PR 创建）需推送到 GitHub 后观察**，
  推送后建议先手动 `workflow_dispatch` 跑一次确认，不必等次日 cron。

## 运维说明

- 每日 PR 人工浏览报告后即可合并归档；docs 更新另行人工提交；
- 若某日无新增条目，`create-pull-request` 检测到无变更会自动跳过，不产生空 PR；
- 信源调整只需改 `src/config/sources.ts`，工作流无需变动。
