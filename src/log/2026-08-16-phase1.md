# 2026-08-16 · Phase 1：采集链路落地

> 承接 `2026-08-16-plan.md`。本文记录 Phase 1（RSS 采集）的实现与验证结果。

## 实现内容

- `src/lib/fetch.ts` — RSS/Atom 抓取与解析：15s 超时、2 次重试（指数退避）、
  自定义 UA；基于 `fast-xml-parser` 同时兼容 RSS 2.0 与 Atom；
  摘要去 HTML 标签并截断 200 字符；条目归一化为 `CollectedItem`。
- `src/lib/dedupe.ts` — 指纹去重：`SHA-1(link + 规范化标题)` 取前 16 位；
  状态持久化在 `src/data/state.json`（key 排序，保证 git diff 稳定），提交仓库支撑增量采集。
- `src/scripts/collect.ts` — 采集入口：顺序抓取（信源间 1s 礼貌延迟），
  单信源失败不影响整体；结果写入 `src/data/raw/YYYY-MM-DD.json`。
- 新增 devDependencies：`tsx ^4.23.12`、`fast-xml-parser ^5.11.0`；
  新增 npm script：`npm run collect`。

## 验证结果（2026-08-16 本地实测）

| 信源 | 抓取条数 |
|---|---|
| 量子位 | 10 |

- 首次运行：60 条全部新增，`state.json` 记录 60 个指纹；
- 同日二次运行：新增 0 条（去重生效）。

## 过程中修复的问题

- **同日重复运行覆盖留档**：初版直接覆写 `raw/YYYY-MM-DD.json`，二次运行会把
  当日上午的新增条目冲掉。已修复为「与既有留档按 fingerprint 合并」，stats 按信源累加。
- npm 安装时 esbuild 的 postinstall 被 allow-scripts 策略拦截，但 tsx 运行正常
  （tsx 4.x 使用预编译二进制，未受影响）。若 CI 出现异常，需
  `npm approve-scripts` 或改用 `npm ci --ignore-scripts=false` 观察。
