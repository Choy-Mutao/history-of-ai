# 2026-08-16 · 信源采集子系统立项计划

> 开发记录第 1 篇。本文记录 `src/` 子系统的立项背景、目标、选型与分阶段计划。
> 已经用户确认并批准。

## 背景与目标

为项目引入国内信源采集能力，服务三个长期目标：

1. **实时追踪** —— 定时采集国内 AI 领域最新动态与研究报告；
2. **真实性校验** —— 同一事件多信源交叉验证，为内容核实提供依据；
3. **可靠性保障** —— 采集结果仅产出「候选更新报告」，人工审核后才写入 docs（符合 AGENTS.md「真实性最高优先级、绝不编造」原则）。

## 已确认选型（2026-08-16 与用户确认）

- 语言：**Node.js + TypeScript**（与现有工具链一致，`type: module`，用 `tsx` 运行）
- 调度：**GitHub Actions cron**（仓库已有 Actions 体系）
- 更新方式：**人工审核后手动更新 docs**（脚本绝不自动写 docs）

## 目录结构

```
src/
├── README.md                # 子系统说明：架构、命令、如何新增信源
├── config/
│   └── sources.ts           # 信源注册表（TS 文件，免 YAML 依赖，带类型校验）
├── lib/
│   ├── types.ts             # Source / CollectedItem / VerifyResult / DedupeState 类型
│   ├── fetch.ts             # RSS/Atom 抓取：超时、重试、UA、限流（Phase 1）
│   ├── dedupe.ts            # 基于指纹的去重，读写 data/state.json（Phase 1）
│   └── verify.ts            # 交叉验证：标题相似度 + 日期邻近（Phase 2）
├── scripts/
│   ├── collect.ts           # 采集入口（Phase 1）
│   └── report.ts            # 候选更新报告生成（Phase 2）
├── data/
│   ├── state.json           # 已见条目指纹（提交仓库，增量去重）
│   └── raw/YYYY-MM-DD.json  # 每日原始采集结果（留档）
├── reports/                 # 候选更新报告（人工审核入口）
└── log/                     # 开发记录（本目录）
```

全部在 `docs/` 之外，不影响 `npm run docs:build`。
新增 devDependencies：`tsx`、`fast-xml-parser`（Node 22 自带 fetch）。

## 交叉验证设计（Phase 2）

- 对同日（±1 天）条目做标题相似度聚类（分词后 Jaccard / 包含关系，规则实现，不引入 NLP 库）；
- 同一事件被 ≥2 个相互独立信源报道 → `corroborated: true`；
- 单信源事件在报告中标注「待核实」；官方/智库类高可靠信源单独列出。

## 报告格式（Phase 2）

`reports/YYYY-MM-DD.md`：按主题聚类分组；每条含标题、日期、信源列表（带链接）、
验证状态，并附「建议更新位置」（本纪/世家/列传/书/年表的候选章节）。
人工审核后才据此手动更新 docs 与 `docs/.vitepress/data/timeline.ts`。

## GitHub Actions（Phase 3）

`.github/workflows/collect.yml`：`cron '17 1 * * *'`（北京时间约 9:17，避开整点）
+ `workflow_dispatch`；Node 22 → `npm ci` → `npm run collect`；
用 `peter-evans/create-pull-request` 将 `data/state.json`、`data/raw/`、`reports/`
提交为自动 PR，人工浏览报告后合并归档；docs 更新另行人工提交。

## npm scripts（Phase 1 落地时添加）

```json
"collect": "tsx src/scripts/collect.ts",
"collect:report": "tsx src/scripts/report.ts"
```
